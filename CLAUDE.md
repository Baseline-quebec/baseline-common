# baseline-core

Shared knowledge base of Baseline developers: reusable modules (`core/`), how a service is built
on top of them (`service/`), how services chain into a flow (`orchestrator/`), and the records
they exchange (`data_schema/`). Projects generated by baseline-app-template copy the modules they
need. The layout and the rules are in `README.md`, `docs/architecture-services.md` and
`docs/rules.md`.

## Conventions

This project follows the Baseline development conventions
(`/home/francois-alexandre-tremblay/Documents/agents-dev/programmation/knowledge/conventions-baseline.md`).

- **Language**: code, commits, branches and PRs in English; user-facing docs (README, `docs/`) in French.
- **Imports**: absolute only (`from baseline_core.module import X`).
- **Type hints**: required everywhere, mypy strict.
- **Docstrings**: Google convention.
- **Line length**: 99.
- **One extra per module** in `pyproject.toml`: a module's dependencies go in its extra, never in
  `dependencies`.

## Commands

Always use `uv run` so commands run in `.venv/`.

```bash
uv sync --all-extras      # install every module's dependencies
uv run ruff check .       # lint
uv run ruff format .      # format
uv run mypy               # type check (strict)
uv run pytest             # tests (architecture rules in tests/architecture_test.py)
```

## Git workflow

- **Branches**: `feat/`, `fix/`, `refactor/`, `docs/` + kebab-case description
- **Commits**: Conventional Commits, `feat(scope): description`
- **PRs**: squash merge only. Never commit directly to `main`.
